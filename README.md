# Сервер сборки промптов — начальный прототип

Gateway предоставляет `POST /api/v1/prompts/compose` и обращается к Prompt Service по gRPC. Сервис загружает опубликованную версию шаблона и параметры из PostgreSQL. Пример данных находится в `database/demo.sql` (применять только один раз). Результат предназначен для просмотра и редактирования клиентом; интерфейс чата пока не реализован.

Для локального запуска из этой папки: `docker compose up --build`. API доступен на `http://localhost:8000/docs`. PostgreSQL и Redis предусмотрены в окружении, но пока не используются сервисами. Пароль PostgreSQL предназначен только для локальной разработки.

Реализованы регистрация, вход, обновление и отзыв сессии, получение текущего пользователя. Управление версиями, история и персонализация пока не реализованы. Внутренний gRPC открыт только в сети Compose; для реального развёртывания потребуется защита соединений и авторизация, ограничение частоты входа и безопасная доставка токенов.

## Начальная схема PostgreSQL

При первом запуске PostgreSQL с новым томом скрипты `database/init` создают базы `identity` и `prompts` и их таблицы. Эти скрипты инициализируют только новый том и не применяют изменения к уже существующему: для дальнейших изменений потребуется механизм миграций. Не удаляйте существующий том ради повторной инициализации: он может содержать данные.

Prompt Service читает опубликованные шаблоны; правила неизменяемости опубликованных версий, сохранения истории по настройке пользователя и удаления данных между сервисами ещё предстоит реализовать. Redis и PostgreSQL используют локальные настройки разработки, не предназначенные для публичного развёртывания.

Prompt Service требует переменные `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`. При запуске Compose переменные `PROMPT_DB_USER` и `PROMPT_DB_PASSWORD` передаются в сервис как `DB_USER` и `DB_PASSWORD`; следует создать пользователя с правом SELECT только на таблицы каталога. Контейнер PostgreSQL и локальный PostgreSQL — разные экземпляры: данные, загруженные в один из них, не появляются автоматически в другом. `demo.sql` не запускается автоматически.

Identity Service требует те же переменные подключения к своей базе `identity`. В Compose используются `IDENTITY_DB_USER` и `IDENTITY_DB_PASSWORD`; пользователь БД должен иметь необходимые права на users, roles, user_roles и auth_sessions. Для уже существующей базы однократно применяется `database/migrations/identity/001_sessions.sql`. Отдельная учётная запись для Identity Service пока не создана.
