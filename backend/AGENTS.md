# Правила проекта

- Перед изменениями описывать шаги, объяснять, зачем и как они будут реализованы, и ждать одобрения пользователя. Не приступать к реализации и изменениям до получения одобрения.
- Не запускать полную сборку проекта без разрешения пользователя.

## Сообщения коммитов

Использовать формат `type: short description`. Описание писать на английском языке, с маленькой буквы, без точки в конце. Допускается прошедшее время, например `feat: added template catalog and rule bindings`.

- `feat` — новая возможность.
- `fix` — исправление ошибки.
- `test` — добавление или изменение тестов.
- `docs` — изменения документации.
- `refactor` — изменение кода без изменения поведения.
- `chore` — настройки и служебные изменения.
- `db` — изменения схемы базы данных; дополнительный тип проекта.
